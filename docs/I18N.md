# Langues de l'interface

Trame est disponible en **français** (langue de référence), **anglais**, **allemand** et **espagnol**. Le choix se fait depuis le sélecteur 🌐 en bas de la barre latérale gauche : le changement est immédiat (sans redémarrer), mémorisé pour les lancements suivants, et suivi par l'écran de l'orateur. Sans choix enregistré, Trame prend la première langue des préférences du système qu'il connaît, sinon l'anglais.

Tout fonctionne hors ligne : les catalogues sont des fichiers TypeScript compilés avec l'application, sans service ni dépendance.

## Ajouter une langue

1. Copier `src/shared/i18n/locales/en.ts` vers `src/shared/i18n/locales/<code>.ts` (par ex. `it.ts`) et renommer la constante exportée (`export const it: Catalog = { … }`).
2. Traduire les textes. Le compilateur (`npm run typecheck`) refuse un catalogue auquel il manque une clé ou qui en a une en trop ; les `{variables}` doivent être conservées telles quelles (`{count}`, `{name}`…).
3. Ajouter **une ligne** dans `LOCALES` (`src/shared/i18n/index.ts`) : `{ code: 'it', name: 'Italiano', catalog: it }`, avec l'import correspondant.
4. Lancer `npm test` : `src/shared/i18n/i18n.test.ts` vérifie automatiquement pour chaque langue qu'elle a les mêmes clés que le français, les mêmes variables, aucun texte vide, la même forme (texte simple ou pluriel) et qu'elle n'est pas restée une copie du français.

Le sélecteur de langue, la détection de la langue du système et les boîtes de dialogue du processus principal prennent la nouvelle langue sans autre modification.

## Fonctionnement

- **Catalogues** (`src/shared/i18n/locales/*.ts`) : un objet à clés plates (`'toolbar.save'`) dont chaque valeur est un texte ou un pluriel `{ one, other }` (et `zero` si besoin). Le type de `fr.ts` définit les clés valides (`MessageKey`) : écrire `t('toolbar.sav')` est une erreur de compilation.
- **Cœur** (`src/shared/i18n/core.ts`, sans dépendance, partagé par l'interface et le processus principal) : `interpolate` (remplace `{nom}`), `pick` (choisit la forme plurielle selon `Intl.PluralRules` de la langue), `makeTranslator` (clé absente d'une langue → texte français ; absente aussi du français → la clé elle-même, visible à l'écran), `matchLocale` (préférences du système → langue).
- **Interface** (`src/renderer/src/i18n.ts`) : le store `useLocale` (langue courante, enregistrée dans `localStorage` sous `trame.lang`), `useT()` pour les composants (ils se redessinent au changement de langue) et `t()` pour le code hors composant (actions, messages d'erreur, résumés d'import). L'attribut `lang` de `<html>` suit la langue. L'écran de l'orateur, autre fenêtre de la même origine, écoute l'événement `storage`.
- **Processus principal** (`src/main/i18n.ts`) : `tm()` traduit les boîtes de dialogue natives, les filtres de fichiers, les erreurs et les crédits de photos. L'interface lui indique la langue choisie (`i18n:set`) au démarrage et à chaque changement ; au tout premier lancement il prend celle du système.
- **Dates, heures, nombres** : `Intl` avec la langue courante (`formatDate.ts`, heure de l'écran de l'orateur).

## Écrire un texte

```ts
const t = useT()                         // composant
<button title={t('toolbar.save.title')}>{t('toolbar.save')}</button>

t('export.warning', { count: 3 })        // hors composant, pluriel selon `count`
```

Règles à suivre pour que les traductions restent possibles :

- **Pas de phrase assemblée à partir de morceaux** (`'Page ' + n + ' sur ' + total`) : une seule clé avec des variables (`'Page {n} sur {total}'`), car l'ordre des mots change d'une langue à l'autre.
- **Pluriels** : une clé `{ one, other }` et la variable `count`, jamais `'s'` ajouté à la main. Une phrase qui compte deux choses (« 3 occurrences dans 2 pages ») utilise deux clés pluriel, la seconde passée à la première en variable (voir `find.status`).
- **Données à libellé** (formes, transitions, filtres, polices) : la donnée garde un identifiant stable (`'fade'`, `'bw'`), le libellé est cherché par `t(\`transition.${id}\`)`. L'identifiant n'est jamais traduit.
- **Contenu créé par l'utilisateur** (noms de calques, textes) n'est jamais traduit. Les textes par défaut (« Votre texte », « Sans titre », texte des modèles) le sont **à la création** : un document créé en français reste en français si l'on change de langue.
- Un test (`usage.test.ts`) refuse les clés que plus aucun code ne lit.

## Ce qui n'est pas traduit

- Les menus du système (menu de l'application macOS, menu contextuel, boutons « Copier / Coller » du système) suivent la langue du système, pas celle de Trame.
- Les noms propres (Trame, Openverse, PowerPoint…), les formats (PDF, PNG…) et les noms des polices.
- Les journaux de la console (diagnostic, en français ou en anglais selon l'endroit).
- Le contenu de la documentation Markdown, rédigée en français.
- Les textes que l'utilisateur ou une source externe écrit (noms de photos, de fichiers, crédits déjà insérés dans un document).
